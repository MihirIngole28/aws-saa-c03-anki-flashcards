SQS – pattern, key traits, exam scenarios?	Queue (Point-to-Point pull). Pull model; messages stored up to 14 days; at-least-once (Standard) or exactly-once (FIFO). Keywords: “decouple”, “buffer requests”, “worker pool”, “async processing”.	Messaging SQS
SNS – pattern and exam scenarios?	Pub/Sub (Push fan-out). Push model; up to 12.5 M subscribers per topic; no persistence; many protocols (SQS, Lambda, HTTP, email). Keywords: “fan-out”, “notify multiple services”, “event broadcasting”.	Messaging SNS
EventBridge – pattern and when to use?	Event bus (Pub/Sub + Rules). Event routing with filter rules; integrates 200+ AWS services + SaaS apps; schema registry. Keywords: “event-driven”, “route events from AWS services”, “SaaS integration”.	Messaging EventBridge
Kinesis Data Streams vs Firehose vs Analytics?	Data Streams: Real-time streaming; retain 24 hrs–365 days; multiple consumers; ordered within shard; replay.<br>Firehose: Fully managed delivery to S3/Redshift/OpenSearch; near-real-time (buffer 60 s or 5 MB).<br>Analytics: Real-time SQL (or Flink) on streams for aggregations / anomaly detection.	Messaging Kinesis
MSK vs Amazon MQ – when to choose each?	MSK: Managed Apache Kafka; Kafka API compatible; existing Kafka workloads; exactly-once; long retention.<br>MQ: Managed ActiveMQ / RabbitMQ; for migrating on-prem apps that use JMS/AMQP/MQTT/STOMP.	Messaging
Standard SQS vs FIFO SQS – key differences?	Standard: Best-effort ordering; at-least-once; nearly unlimited throughput; no deduplication.<br>FIFO: Strict FIFO per Message Group ID; exactly-once; 300 msg/s (3,000 with batching); 5-min deduplication window; name must end in .fifo.	Messaging SQS
SQS Visibility Timeout – what it is and tip?	Duration a message is hidden after a consumer receives it (default 30 s, max 12 h). If not deleted, it becomes visible again.<br>Tip: Set it longer than your maximum processing time so a crashed consumer doesn’t cause duplicate processing.	Messaging SQS
SQS other important limits?	Message Retention: 4 days default, max 14 days.<br>Message Size: 256 KB (use Extended Client Library + S3 for up to 2 GB).<br>Long Polling: up to 20 s (reduces empty responses and cost).<br>Dead Letter Queue: messages that fail maxReceiveCount times.<br>Delay Queue: delay delivery of new messages up to 15 minutes.	Messaging SQS
When to choose SNS vs SQS vs EventBridge vs Kinesis?	Fan-out to multiple services at once → SNS → multiple SQS queues.<br>Decouple + buffer spikes → SQS.<br>Route events from 200+ AWS / SaaS services with rules → EventBridge.<br>Real-time stream + replay + multiple consumers → Kinesis Data Streams.<br>Deliver streaming data to S3/Redshift without managing consumers → Firehose.<br>Migrate existing RabbitMQ/ActiveMQ → Amazon MQ.<br>Kafka workload → MSK.	Messaging
Kinesis shard capacity and Enhanced Fan-Out?	1 MB/s write, 2 MB/s read per shard. Scale by splitting or merging shards.<br>Enhanced Fan-Out: each consumer gets its own dedicated 2 MB/s pipe (instead of sharing the 2 MB/s).	Messaging Kinesis
Kinesis mnemonic?	Streams = Real-time + Replay + Multiple consumers.<br>Firehose = Load + Near-real-time + Delivery to S3/Redshift/OpenSearch.<br>Analytics = SQL on streams.<br>Streams needs you to manage producers/consumers; Firehose is fully managed ingestion.	Messaging mnemonic
CloudWatch Metrics – what it monitors and exam triggers?	Performance metrics (CPU, network, custom). 15 months retention by default; detailed monitoring = 1-min granularity. Keywords: “monitor CPU”, “set alarm”, “auto scaling trigger”.	Monitoring CloudWatch
CloudWatch Logs – key facts?	Log ingestion from EC2, Lambda, RDS, VPC Flow Logs, etc. Retention configurable per log group (1 day to 10 years). Keywords: “centralize logs”, “filter log events”, “log insights query”.	Monitoring CloudWatch
CloudWatch Alarms – what they do?	Triggered when a metric crosses a threshold. Actions: SNS, Auto Scaling, EC2 action. Keywords: “notify when CPU > 80%”, “scale when latency > 500 ms”.	Monitoring CloudWatch
CloudWatch Events / EventBridge – use cases?	React to AWS API events (cron schedule or event pattern). Routes to targets (Lambda, SQS, etc.). Keywords: “trigger Lambda on schedule”, “react to EC2 state change”.	Monitoring EventBridge
CloudTrail – what it records?	AWS API calls (who did what when). 90-day event history free; store in S3 for longer. Keywords: “audit API calls”, “who deleted S3 bucket”, “compliance trail”.	Monitoring CloudTrail
AWS Config – what it tracks?	Resource configuration changes + compliance rules. Configuration timeline; non-compliant alerts. Keywords: “are resources compliant”, “config drift”, “remediation”.	Monitoring Config
X-Ray – what it provides?	Distributed tracing for applications. Service maps, latency analysis, error analysis. Keywords: “trace requests across microservices”, “find bottleneck”, “latency root cause”.	Monitoring X-Ray
Exam trap – CloudTrail vs CloudWatch vs Config?	CloudTrail = WHO called what API (audit).<br>CloudWatch = HOW is the system performing (metrics/logs).<br>Config = IS the resource compliant with rules (configuration state).<br>Three different questions.	Monitoring exam-trap
AWS WAF – what it does and layer?	Web Application Firewall; rules against SQL injection, XSS, bad bots, geo-blocks. Layer 7; attaches to CloudFront, ALB, API Gateway, AppSync. Keywords: “block SQL injection”, “protect against OWASP Top 10”, “geo-block countries”.	Security WAF
Shield Standard vs Shield Advanced?	Standard: Automatic Layer 3/4 DDoS protection for all AWS customers at no cost. Always on.<br>Advanced: $3,000/month; enhanced protection + 24/7 DDoS Response Team + cost protection. Keywords: “sophisticated DDoS”, “financial protection”, “DRT support”.	Security Shield
AWS Firewall Manager – purpose?	Centrally deploy and manage WAF rules, Shield Advanced, Security Groups, Network Firewall across an AWS Organization. Keywords: “apply WAF rules across all accounts”, “organization-wide security policies”.	Security
GuardDuty – what it does?	Threat detection using ML on CloudTrail, VPC Flow Logs, DNS Logs, S3 logs, EKS logs. Account-level threat intelligence. Keywords: “detect cryptomining”, “suspicious API calls”, “unauthorized access”.	Security GuardDuty
Inspector – what it does?	Automated vulnerability assessment for EC2, ECR images, Lambda functions (CVE detection). Keywords: “scan EC2 for vulnerabilities”, “container image scanning”.	Security Inspector
Macie – what it does?	ML-based PII / sensitive data discovery and classification in S3. Keywords: “find PII in S3”, “GDPR compliance”, “sensitive data discovery”.	Security Macie
Security Hub – purpose?	Aggregates findings from GuardDuty, Inspector, Macie, Config into a unified dashboard. Keywords: “single pane of glass for security”, “normalize findings”.	Security
AWS Network Firewall – what it provides?	Managed stateful firewall (Suricata rules) for VPC; deep packet inspection. Keywords: “deep packet inspection”, “IDS/IPS in VPC”, “custom domain filtering”.	Security
Secrets Manager vs Parameter Store – exam decision?	Secrets Manager: ~$0.40/secret/month; designed for secrets; auto-rotates credentials (with Lambda).<br>Parameter Store: Free for standard parameters; no auto-rotation (you must trigger Lambda yourself).<br>Exam: “auto-rotate database credentials” → Secrets Manager.	Security exam-trap
KMS vs CloudHSM?	KMS: Create and manage encryption keys; integrates with 100+ AWS services; customer-managed keys, key rotation, envelope encryption.<br>CloudHSM: Dedicated Hardware Security Module; you manage keys entirely; FIPS 140-2 Level 3. Keywords: “FIPS 140-2 Level 3”, “full key control”, “PKCS11 / JCE”.	Security
Security services mnemonic (GuardDuty / Inspector / Macie)?	GuardDuty = Guard dog (threat DETECTION).<br>Inspector = Home inspector (vulnerability SCANNING).<br>Macie = Mac & Privacy (PII / data CLASSIFICATION).<br>Three different jobs: detect threats, find vulnerabilities, classify data.	Security mnemonic
