VPC key limits and CIDR range?	Max 5 VPCs per region (soft limit). CIDR range /16 to /28. Spans all AZs in a region.	VPC
Subnet – public vs private and IP reservation?	Public = has route to Internet Gateway. Private = no IGW route. AWS reserves 5 IPs per subnet (first 4 + last).	VPC
Internet Gateway (IGW) – key facts?	Enables internet access for public subnets. Horizontally scaled, highly available, no bandwidth limit. One IGW per VPC. Attach to VPC and add route in the public subnet’s route table.	VPC
NAT Gateway – purpose and HA exam trap?	Allows private-subnet instances to initiate outbound internet connections while blocking inbound. Deployed in a public subnet and uses an Elastic IP.<br>Exam trap: NOT highly available across AZs by default. For true HA, deploy one NAT Gateway per AZ and route each private subnet to the NAT Gateway in its own AZ.	VPC exam-trap
Security Group vs NACL – core differences?	Security Group: Instance (ENI) level; Stateful (return traffic auto-allowed); Allow only; all rules evaluated together; Deny all inbound / allow all outbound by default.<br>NACL: Subnet level; Stateless (must allow both directions); Allow AND Deny; numerical order (lowest first); Allow all by default (default VPC NACL).	VPC
Security Group powerful pattern?	Security Groups can reference other Security Groups by ID (not just CIDR). Example: allow inbound from “sg-webserver” to “sg-database” without knowing IP addresses. Correct pattern for tiered application security.	VPC
VPC Peering – key limitations?	Direct private connection between two VPCs (same or different account/region). NOT transitive (A↔B and B↔C does not give A↔C). No overlapping CIDRs allowed.	VPC
VPC Endpoints – Gateway vs Interface?	Gateway (S3, DynamoDB): free.<br>Interface (most other services): hourly cost + data transfer.<br>Both provide private connection to AWS services without going over the internet.	VPC
Transit Gateway (TGW) – when to use?	Hub-and-spoke connectivity for many VPCs + on-premises. Transitive routing. One TGW can handle thousands of VPCs. Uses its own route tables and can be shared via Resource Access Manager (RAM).	VPC
AWS PrivateLink – key characteristics?	Expose a service to other VPCs without peering. Service runs behind an NLB; consumers get an Interface Endpoint. Unidirectional; does not expose the full VPC.	VPC
Site-to-Site VPN vs Direct Connect?	Site-to-Site VPN: Encrypted IPSec over public internet. Fast to set up (~hours). Variable latency. Up to 1.25 Gbps per tunnel.<br>Direct Connect: Dedicated private line. Consistent low latency. 1/10/100 Gbps. No encryption by default. Long setup (weeks/months).<br>Need both consistency + encryption → Direct Connect + VPN.	VPC
VPN / Direct Connect mnemonic?	VPN = Variable/Virtual (over internet, encrypted, variable latency).<br>DX = Dedicated eXpress (physical line, consistent, no encryption by default).	VPC mnemonic
VPC Flow Logs – what they capture and what they do NOT capture?	IP traffic metadata (not packet contents) for VPC, subnet, or ENI. Can go to CloudWatch Logs, S3, or Kinesis Data Firehose.<br>Do NOT capture: DNS traffic, Windows license activation, 169.254.x.x (instance metadata), DHCP traffic.<br>Use cases: troubleshoot connectivity, security analysis, compliance auditing.	VPC
Simple routing policy – how it works and use case?	Maps domain to one or more resources; random selection if multiple values. Use for single resource or basic DNS / single endpoint.	Route53
Weighted routing policy – how it works and exam keywords?	Split traffic by weights (0–255); weight 0 = no traffic. Keywords: “split 10% to new version”, “blue/green”, “canary”, A/B testing, gradual migration.	Route53
Latency-based routing – when to use?	Routes to the region with lowest network latency for the user. Keywords: “lowest latency”, “fastest response for users globally”, multi-region apps.	Route53
Failover routing – how it works and use case?	Active-Passive; routes to secondary when primary health check fails. Keywords: “failover”, “DR”, “primary fails → secondary”.	Route53
Geolocation routing – how it works and use cases?	Routes based on user’s geographic location (continent, country, state). Keywords: “users in Europe to EU servers”, “data residency”, “localization”, GDPR.	Route53
Geoproximity routing – how it differs from Geolocation?	Routes based on location + optional bias to shift traffic toward/away from a region. Used for fine-grained traffic engineering (expand/shrink region coverage).<br>Exam trap: Geolocation is STRICT (France → EU endpoint). Geoproximity is about traffic engineering with bias.	Route53 exam-trap
Multi-Value Answer routing – what it does and limitation?	Returns up to 8 healthy records (Simple + health checks). Client-side load balancing across multiple endpoints. NOT a replacement for ELB.	Route53
IP-Based routing – when to use?	Routes based on client IP CIDR blocks you define. Keywords: “route specific IP ranges”, “ISP-based routing”, cost optimization.	Route53
Route 53 Health Check types?	Endpoint: HTTP/HTTPS/TCP to a specific IP/hostname (15 global checkers; 3/5 threshold).<br>Calculated: Aggregate multiple checks with AND/OR logic.<br>CloudWatch Alarm: Health based on CW metric/alarm state (use for private resources with no internet access).	Route53
CloudFront Origin – common types and S3 best practice?	S3, ALB, EC2, API Gateway, any HTTP server. For private S3 use Origin Access Control (OAC) — not the legacy OAI. ALB/EC2 origins must be publicly accessible or use VPC Origin.	CloudFront
CloudFront Distribution – key capability?	One distribution can have multiple origins with different path patterns (e.g., /api/* → ALB, /* → S3).	CloudFront
Edge Location vs Region/AZ?	400+ global Points of Presence that cache content. Not the same as a Region or Availability Zone.	CloudFront
Cache Behaviors – important ordering rule?	Rules for how CloudFront caches and routes requests based on path patterns. Order matters — more specific paths should be listed first.	CloudFront
CloudFront TTL control?	Controlled by Cache-Control and Expires headers; can be overridden in the CloudFront behavior (Minimum TTL, Default TTL, Maximum TTL). CloudFront uses the minimum of Max TTL and the header value.	CloudFront
Origin Access Control (OAC) – purpose?	Grants CloudFront permission to access a private S3 bucket so users cannot access the S3 URL directly (bypassing CloudFront). Replaces the older OAI.	CloudFront
Signed URLs vs Signed Cookies?	Signed URL: Restricts access to one specific file.<br>Signed Cookies: Restricts access to multiple files / membership-style access.<br>Both signed with a trusted key pair for authenticated users.	CloudFront
WAF integration with CloudFront?	AWS WAF on CloudFront protects at the edge (globally). Stops attacks before they reach the origin (geo-blocking, rate limiting, SQL injection protection, etc.).	CloudFront WAF
Lambda@Edge vs CloudFront Functions?	CloudFront Functions: Run at edge location; very light (< 1 ms, < 2 MB).<br>Lambda@Edge: Run at regional edge; heavier (up to 30 s, 10 GB RAM).<br>Both used for auth, A/B testing, URL rewrites, etc.	CloudFront
Field-Level Encryption – what it does?	Encrypts specific POST fields (e.g., credit-card numbers) at the edge; only designated origin servers can decrypt. Used for PCI compliance / protecting sensitive fields beyond HTTPS.	CloudFront
CloudFront vs S3 Transfer Acceleration?	Both use the AWS edge network. CloudFront = CDN primarily for content delivery (reads). S3 Transfer Acceleration = specifically accelerates S3 PUT uploads from distant clients via the AWS backbone.	CloudFront S3
ALB vs NLB vs GWLB – OSI layer and protocols?	ALB: Layer 7 (HTTP/HTTPS/WebSocket/gRPC)<br>NLB: Layer 4 (TCP/UDP/TLS)<br>GWLB: Layer 3+4 (IP packets; GENEVE encapsulation)	ELB
ALB – typical use cases and exam keywords?	Web apps, microservices, content-based routing, Lambda targets. Keywords: “HTTP routing”, “host/path-based routing”, “microservices”, “Lambda”.	ELB
NLB – typical use cases and exam keywords?	TCP apps, gaming, IoT, extreme performance, static IP needs. Keywords: “static IP”, “TCP”, “extreme performance”, “UDP”, “gaming”. Provides Elastic IP per AZ.	ELB
GWLB – typical use case and exam keywords?	Deploy third-party virtual appliances (Palo Alto, Fortinet, etc.) for security inspection. Keywords: “intrusion detection”, “firewall appliance”, “security inspection”.	ELB
Sticky sessions support?	ALB: Yes (application-based or duration-based cookies)<br>NLB: Yes (source IP)<br>GWLB: No	ELB
Fixed / static IP addresses?	NLB provides static Elastic IPs (one per AZ). ALB has no fixed IPs. Common pattern: put NLB in front of ALB to get fixed IPs while keeping Layer 7 routing.	ELB exam-trap
ALB advanced routing features?	Host-based, Path-based, HTTP header, HTTP method, Query string routing. Also supports Fixed response, Redirect actions (e.g., HTTP→HTTPS), and Lambda as a target.	ELB
Connection Draining / Deregistration Delay – what it is and exam tips?	When an instance is deregistered or becomes unhealthy, existing connections stay alive for up to 3600 s (default 300 s) so in-flight requests can finish.<br>Long-running uploads interrupted during deployments → increase the delay.<br>Deployments slow because instances stay in draining too long → decrease the delay.	ELB
