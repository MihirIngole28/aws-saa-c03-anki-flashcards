Classic Highly Available Web Application pattern – key layers?	DNS: Route 53 (Latency or Failover)<br>CDN: CloudFront<br>LB: ALB (Multi-AZ)<br>Web: EC2/ASG (or ECS/Fargate) across 2+ AZs<br>App: EC2/Lambda in private subnets across 2+ AZs<br>Cache: ElastiCache Redis (replicated)<br>DB: Aurora Multi-AZ or RDS Multi-AZ + Read Replicas<br>Storage: S3<br>Secrets: Secrets Manager / Parameter Store<br>Network: VPC public/private subnets + NAT Gateway per AZ	Patterns
Serverless Architecture pattern – main services?	API: API Gateway (REST or HTTP)<br>Compute: Lambda<br>DB: DynamoDB (On-Demand)<br>Cache: DAX or ElastiCache<br>Auth: Cognito User Pools + Identity Pools<br>Storage: S3<br>Events: EventBridge or SNS + SQS<br>CDN: CloudFront (for SPA + API)	Patterns
REST API vs HTTP API in API Gateway – when to choose which?	HTTP API is ~71% cheaper and has lower latency.<br>REST API adds: usage plans, API keys, request transformation, WAF, resource policies, edge-optimized.<br>Exam: Need usage plans / throttling per client or WAF → REST API. Otherwise → HTTP API.	Patterns APIGateway
Disaster Recovery strategies – RTO / RPO / Cost ranking?	Backup & Restore: Hours / Hours / Lowest<br>Pilot Light: 10s of minutes / Minutes / Low<br>Warm Standby: Minutes / Seconds–minutes / Medium<br>Multi-Site Active/Active: Near zero / Near zero / Highest	Patterns DR
DR strategies mnemonic?	BR-PP-WS-AA = Backup-Restore (hours), Pilot-light (minutes), Warm-Standby (minutes, more ready), Active-Active (near zero). Cost goes UP as RTO/RPO goes DOWN.	Patterns mnemonic
Data Lake architecture – main layers and services?	Ingestion: Kinesis / Firehose, DMS, DataSync, Snowball<br>Raw storage: S3 (partitioned)<br>Catalog: Glue Data Catalog<br>ETL: Glue (Spark), Lambda<br>Curated storage: S3 (Parquet/ORC)<br>Query: Athena<br>Visualization: QuickSight<br>Warehouse (heavy OLAP): Redshift (+ Spectrum)	Patterns
Event-Driven Decoupled Architecture – common patterns?	Order placed → notify multiple services: SNS → multiple SQS queues (fan-out)<br>Batch with retry: SQS → ASG workers → DLQ<br>React to CloudTrail events: EventBridge rule → Lambda remediation<br>Process uploaded files: S3 Event → SQS → Lambda/ECS<br>Complex workflow with compensation: Step Functions	Patterns
Well-Architected Framework – 6 Pillars and core focus?	1. Operational Excellence – run & monitor systems (CloudFormation, CloudWatch, Config, X-Ray, SSM)<br>2. Security – protect information (IAM, KMS, CloudTrail, GuardDuty, WAF, etc.)<br>3. Reliability – recover from failures & meet demand (ASG, Multi-AZ/Region, backups)<br>4. AWS DMS – what it migrates and key features?	Databases (homogeneous or heterogeneous). Minimal downtime; continuous replication (CDC). Use Schema Conversion Tool (SCT) for heterogeneous migrations (e.g., Oracle → PostgreSQL).	Migration
Application Migration Service (MGN) vs older SMS?	MGN migrates physical, virtual, or cloud servers with continuous block-level replication and minimal-downtime cutover. It replaces the older Server Migration Service (SMS).	Migration
Snowball Edge vs Snowmobile – decision rule?	Snowball Edge (Storage Optimized): ~80 TB usable; TBs to PBs; good for limited bandwidth.<br>Snowmobile: 45-foot truck; for > 10 PB (exabyte-scale).<br>Rule of thumb: if network transfer would take > 1 week → use Snow family. < 10 PB → multiple Snowball Edge units; > 10 PB → Snowmobile.	Migration
AWS DataSync – what it does?	Online transfer of file/NFS/SMB/HDFS data to S3, EFS, or FSx. Scheduled sync; agent-based; faster than simple copy over Direct Connect.	Migration
AWS Transfer Family – what it provides?	Managed SFTP / FTP / FTPS endpoints backed by S3 or EFS. Clients keep their existing protocols; no change needed on the client side.	Migration
Athena – purpose and cost tips?	Serverless SQL queries over S3. Pay per query ($5/TB scanned). Use columnar formats (Parquet/ORC) + partitioning to reduce cost. No infrastructure to manage.	Analytics
Redshift – purpose and key features?	Managed columnar data warehouse (OLAP). MPP architecture. Redshift Spectrum queries S3 in place. RA3 nodes decouple compute from storage.	Analytics
EMR – purpose and cost tip?	Managed Hadoop / Spark / Hive / Presto clusters for large-scale data processing. Use transient clusters for batch jobs and Spot instances for task nodes to save money.	Analytics
Glue – what it provides?	Managed ETL + Data Catalog. Serverless Spark ETL jobs. Crawlers auto-discover schema. Data Catalog integrates with Athena, Redshift, EMR.	Analytics
QuickSight – purpose?	Serverless BI and visualization. SPICE in-memory engine; ML-powered insights; pay-per-session; embeddable dashboards.	Analytics
OpenSearch Service – purpose?	Search + log analytics. Elasticsearch API compatible; OpenSearch Dashboards (formerly Kibana); anomaly detection; UEBA.	Analytics
Lake Formation – purpose?	Build, secure, and govern a data lake on S3. Fine-grained access control on the Glue Data Catalog (column/row level security); simplifies data-lake setup.	Analytics
Step Functions – purpose and Standard vs Express?	Serverless workflow orchestration (state machine). Visual workflows with error handling, retries, parallel states.<br>Standard: up to 1-year duration, async.<br>Express: up to 5 minutes, ideal for IoT/streaming high-volume workloads.	AppIntegration
AppFlow – purpose?	No-code SaaS data integration (Salesforce, ServiceNow, Slack → S3, Redshift). Scheduled or event-driven; field-level encryption in transit.	AppIntegration
API Gateway – key capabilities?	Managed API endpoint (REST, HTTP, WebSocket). Supports throttling, caching, API keys, usage plans, mock integration, Cognito/Lambda authorizers.	AppIntegration
AppSync – purpose?	Managed GraphQL service. Real-time data sync via subscriptions (WebSocket); resolvers to DynamoDB, Lambda, HTTP. Ideal for mobile/web apps.	AppIntegration
SWF vs Step Functions?	Prefer Step Functions. SWF is legacy and used when you need human approval steps or external process integration via long-running tasks.	AppIntegration
